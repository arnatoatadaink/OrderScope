## 8. Tagging rule

For each version:

1. identify the accepted cumulative state;
2. verify ancestry or documented semantic equivalence;
3. run release acceptance;
4. write the manifest;
5. only then create an annotated tag.

Do not rewrite published `main` history solely to manufacture visually contiguous intermediate commits. If an exact historical cumulative tree is unavailable, preserve history and use a documented reconstruction/equivalence boundary.
