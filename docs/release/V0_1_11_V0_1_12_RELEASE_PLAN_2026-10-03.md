## 2. v0.1.11 — Crypto On-chain Event Intelligence

### Scope

v0.1.11 introduces a new on-chain event-intelligence lane on top of the already accepted Crypto Market Structure layer (`UWBS-068..079`).

### Critical path

```text

        |
        v

+ candidate-state machine
        |
        v

(price / BTC-relative / OI / funding / liquidation)
        |
        v
REL-11D
C0-004 / UWBS-109
Historical exploit price-impact dataset
+ NEAR Intents replay / false-positive validation
        |
        v
REL-11X
Cumulative v0.1.11 regression / acceptance / TAG READY decision
```

### Dependencies

```text
UWBS-068..079 accepted Crypto Market Structure
        -> REL-11C / C0-003
        -> REL-11D / C0-004
```

### Acceptance boundary

REL-11X requires at minimum:

- focused C0 tests pass;
- affected existing crypto-market-structure tests pass;
- full Python regression passes;
- `python -m compileall` passes;
- `git diff --check` passes;
- affected Worker tests/typecheck pass when shared runtime contracts are touched;
- no abnormal transfer alone is promoted to a confirmed security incident;
- historical replay preserves first-on-chain/public/official timestamp distinctions.

### Acceptance boundary

REL-12X requires at minimum:

- official-release observation timestamps and provenance preserved;
- consensus/prior/revision values are explicit and never silently backfilled;
- deterministic unit-safe surprise computation;
- event windows are no-lookahead and reproducible;
- closed/stale market observations remain UNKNOWN rather than guessed;
- contradictory evidence is retained;
- `CARRY_BUILD/STABLE/COOLING` remain Interpretation, not observed capital-flow Fact;
- `CARRY_UNWIND_CANDIDATE` still requires independent A0-005 evidence;
- focused A0-018 tests pass;
- affected macro/cross-market tests pass;
- full Python regression, compileall and diff checks pass.

## 4. Release ordering

Current planned order:

```text
v0.1.10  ACCEPTED / TAG READY
   |
   v
v0.1.11  Crypto On-chain Event Intelligence
   |
   v
v0.1.12  Macro Release / Yen Carry Observability
```

v0.1.12 depends on existing accepted Macro/Carry foundations, not on the new C0 implementation. The release order is therefore a management/versioning choice rather than a technical dependency between v0.1.11 and v0.1.12.

## 5. Non-authorization boundary

This release plan does not authorize:

- Git tag creation/push;
- live provider activation;
- Worker/Cron mutation;
- remote D1 mutation;
- paid procurement;
- automated trading;
- incident attribution from abnormal transfers alone;
- force push or history rewrite.
